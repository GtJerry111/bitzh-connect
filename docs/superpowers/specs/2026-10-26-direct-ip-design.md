# 直连 IP（不走校园 VPN）设计

日期：2026-10-26
状态：设计已评审，待 spec 审阅
范围：macOS 第一版
相关：[TUN 与其他 TUN 共存](2026-09-20-tun-coexist-design.md)

## 1. 背景

学校 EasyConnect 服务端下发的 IP 资源包含整个 `10.0.0.0/8`。zju-connect 在 TUN 模式下用
`-add-route` 把这个资源集合拆成明细路由加到 `utun6`，于是公司内网的 `10.182.37.18`
也被卷进校园 VPN。公司服务器在校园网侧没有回程路由，新发起的 TCP 连接会 timeout。

已确认的现象与证据：

- VPN 已连接时：`route -n get 10.182.37.18` 命中 `10.128.0.0/10 -> utun6`；
- 公司 SSH 超时，学校 SSH 正常；
- 公司 SSH 先建立、VPN 后连接时旧会话仍可用，因为 macOS/BSD 的 TCP socket
  缓存了连接时的路由；新连接才会重新查表；
- `10.182.37.18` 在公司网络中可通过当前默认物理网关 `10.0.0.1 (en0)` 直达；
- 上游 zju-connect 没有 `-exclude-route` 参数；`-disable-zju-config` 只跳过
  zju-connect 自带的 `10/8` 兜底，不会过滤学校服务端下发的 `10/8`。

因此第一版不改内核、不改学校路由，只在系统路由层给用户指定的公司 IP 加更具体的
`/32` 路由，指回当前物理网关。按最长前缀匹配，公司 IP 走物理网卡，学校 IP 继续走
校园 VPN。

## 2. 目标

VPN 保持连接时：

- 公司 `10.182.37.18` 等多个 IP 走物理网卡；
- 终端 SSH、VS Code/Cursor Remote-SSH、`scp`/`rsync`/SFTP 都能正常工作；
- 学校 `10.8.18.32` 等校园资源仍然走校园 VPN；
- 随时新开公司 SSH 都能连上，不要求“公司 SSH 先连好、VPN 后连”；
- 配置一次后自动生效，断开/重连/异常退出后不残留错误路由。

## 3. 非目标（第一版不做）

- CIDR / 网段排除；
- 域名、主机名、IPv6；
- 每条 IP 指定网卡或网关；
- 自动处理换网后的默认网关变化；
- 跳板机自动识别；
- 保证“路由已加”等于“公司服务 TCP 可达”；
- Linux / Windows 支持；
- 连接中即时同步路由（改配置走“稍后 / 现在重连”）。

## 4. 用户场景与验收标准

### 4.1 核心场景

1. 打开直连 IP，填入 `10.182.37.18`；
2. 连接校园 VPN；
3. 终端 `ssh ai@10.182.37.18` 可连；
4. 终端 `ssh czr@10.8.18.32` 可连；
5. VS Code Remote-SSH 分别连公司、学校均可用；
6. `scp` / `rsync` 对公司、学校均可用；
7. 先开 VPN 再新开公司 SSH 也能连，不要求顺序。

### 4.2 Definition of Done

- 后端路由功能通过单元测试和手工验收；
- 前端 UI 通过第 9 节的 UI 验收清单；
- 深色/浅色主题、TUN 关闭、Linux/Windows 禁用态均检查；
- 关键界面截图与设计稿对照，无明显布局/字号/间距/颜色偏差；
- 不在应用日志、诊断日志、进程参数中新增泄露风险。

## 5. UX 与 UI 设计

### 5.1 高级设置卡片

位置：`高级设置 → 网络`，放在「连接」和「代理」之间。

```text
直连 IP（不走校园 VPN）                    [开关]

这些 IP 会走当前物理网卡；只填公司/其他直连地址，不要填学校地址。

┌──────────────────────────────────────┐
│ ● 10.182.37.18                  [−]  │
│ ● 10.182.37.19                  [−]  │
│ ○ 10.182.37.20                  [−]  │
│                                      │
└──────────────────────────────────────┘
＋ 添加 IP

每行一个 IPv4；空行忽略；自动去重；最多 100 个。
```

规则：

- 开关默认关闭；
- 动态行：输入框 + 删除 `−`；添加 `+` 固定在列表下方；
- 列表区域固定高度约 4–5 行，超出滚动；设置对话框整体高度保持稳定；
- 开关打开且列表为空：自动出现一行空输入并聚焦；
- 删除最后一行后保留一行空输入；只剩一行且为空时删除按钮禁用/隐藏；
- 开关关闭：隐藏列表，保留已填配置；
- TUN 关闭：卡片保持可编辑，提示“仅 TUN 模式生效”，状态点全部灰色；
- Linux：卡片置灰，提示“当前平台暂不支持”；
- Windows：隐藏卡片；
- 列表为空：不报错，等同于功能空闲。

状态点：

```text
绿色 = 当前连接已生效
赭石 = 当前连接尝试过但失败
灰色 = 未连接 / 未应用 / 待下次连接生效
```

### 5.2 菜单栏面板

在「连接模式」下方新增独立行：

```text
⇄  直连 IP            ● 2 个  ›
```

显示规则：

| 条件 | 行为 |
|---|---|
| 功能关闭 | 隐藏 |
| 功能开启，未连接 | 隐藏 |
| 功能开启，已连接，列表为空 | 隐藏 |
| 功能开启，已连接，生效集合为空（全部为本地网段跳过） | 隐藏 |
| 功能开启，已连接，全部成功 | 显示 `● 2 个`，绿色点 |
| 功能开启，已连接，部分失败 | 显示 `1/2`，赭石色 |
| 功能开启，已连接，全部失败 | 显示 `0/2`，赭石色 |
| 代理模式（TUN 关闭） | 隐藏 |

点击整行：打开高级设置，定位到「直连 IP」卡片；卡片内每行显示状态点。

### 5.3 主窗口状态

成功时：

```text
内网 IP 10.0.43.111 · 直连 IP 2/2
```

列表为空或生效集合为空时，不追加“直连 IP”文案。

失败时，在状态副标题下方出现黄色警告条（出现时把统计区往下推，窗口变高）：

```text
⚠ 直连 IP 1/2 已生效
10.182.37.19 未能添加；学校 VPN 不受影响。        查看日志 ›   ×
```

规则：

- 只在失败时出现；成功不显示；
- 可点 `×` 关闭；
- 关闭后菜单栏 `1/2` 仍保留；
- 下次重连、失败集合变化、恢复成功时重新评估；
- 「查看日志」打开日志目录，与高级设置里的入口一致。

### 5.4 重连确认弹窗

自定义对话框，沿用 App 现有视觉风格：

```text
应用直连 IP 配置？

直连 IP 已修改。应用新配置需要断开并重连 VPN，
学校 SSH 会短暂断开；公司 SSH 也需要重新连接。

[稍后]                    [现在重连]
```

- 默认按钮「稍后」；主色强调「现在重连」；
- 设置对话框原有的「取消」负责放弃本次修改；
- 选择「稍后」：保存配置，当前连接不变，下次连接生效；
- 选择「现在重连」：保存后立即断开重连。

### 5.5 视觉规范

- 使用现有 `theme.semantic_color` / `card_background` / 字体层级，不新增品牌色；
- 卡片圆角、间距、说明文字风格与「连接」「代理」卡片一致；
- 输入框使用等宽字体，IP 对齐易读；
- 错误用系统红（`error`），警告用赭石（`working`），成功用品牌绿（`connected`）；
- 深色/浅色/跟随系统三态都要检查；
- 键盘可达：Tab 顺序、删除按钮、添加按钮、保存/取消；
- 文本支持 VoiceOver/辅助功能标签（至少设置 accessibleName）。

## 6. 状态模型

区分两份状态：

| 状态 | 含义 | 展示位置 |
|---|---|---|
| 配置状态 | 开关 + IP 列表，已保存 | 设置卡片 |
| 生效状态 | 当前连接实际加成功的路由 | 菜单栏、状态副标题、警告条、卡片状态点 |

规则：

- 配置变更但选「稍后」：生效状态不变；卡片显示新配置 + 未应用灰点 + “修改将在下次连接生效”；
- 关闭开关但选「稍后」：当前路由仍生效；菜单栏继续显示当前生效数量；卡片提示“当前连接仍生效，重连后关闭”；
- 重连后：按新配置重新计算生效状态；
- 菜单栏始终反映“当前实际生效”，不反映“尚未应用的配置”；
- 配置集合按“IP 集合”比较，不比较顺序；去重后集合未变则不弹重连确认。

## 7. 路由与特权 helper

### 7.1 协议

- `PROTOCOL_VERSION` 从 1 升到 2；
- `CMD_START` 增加可选字段 `direct_ips: list[str]`；
- helper 返回增加：

```json
{
  "ok": true,
  "pid": 123,
  "gateway": "10.0.0.1",
  "interface": "en0",
  "routes": [
    {"ip": "10.182.37.18", "ok": true},
    {"ip": "10.182.37.19", "ok": false, "error": "route_add_failed"}
  ]
}
```

### 7.2 helper 行为

1. 校验 `direct_ips`：
   - 最多 100 条；
   - 每条必须是合法 IPv4；
   - 拒绝 `0.0.0.0`、`255.255.255.255`、回环、组播、广播；
   - 任何 CIDR 形式一律拒绝；
   - 不执行任意命令，只允许 `route` 参数化调用。
2. 探测默认网关：
   - `route -n get default`；
   - 解析 `gateway:` 与 `interface:`；
   - 若取不到、或 interface 是 `utun*`，不添加路由，返回 `route_error`；
   - 不阻断内核启动。
3. 在启动内核前添加路由：
   - `route -n add -host <ip> <gateway>`；
   - 若返回 `File exists`，用 `route -n get <ip>` 检查是否已指向同一物理网关：
     - 是：按成功处理；
     - 否：按失败处理；
   - 每条独立记录成功/失败。
4. 启动内核；若启动失败，删除本次已添加的路由并返回错误。
5. 保存本次实际添加的 IP 列表与 gateway，供停止时清理。
6. 停止内核、内核自行退出时，删除这些路由：
   - `route -n delete -host <ip>`；
   - best-effort，失败只记日志，不阻断停止。
7. helper 重启清理：
   - 添加路由时把 `ip + gateway` 写入 `/var/run/bitzh-connect-direct-routes.json`；
   - helper 启动时读取该文件，best-effort 删除上次遗留路由，然后删除状态文件；
   - 文件不存在/损坏时安静跳过。
8. 安全：
   - 保持现有 socket 0600 + peer uid 校验；
   - 不引入 shell；
   - 只接受 IPv4 `/32` 语义的 IP 字符串；
   - 限制 100 条，避免病态配置。

### 7.3 App 行为

- 连接前若 TUN 模式、开关开启、列表非空：
  - helper 版本 >= 2：把 `direct_ips` 传给 `start`；
  - helper 版本 < 2 或不可用：弹提示：
    - 「更新特权服务」→ 走现有安装/更新流程；
    - 「本次跳过直连 IP 继续连接」→ 不传 `direct_ips`，继续连接；
    - 选择跳过：本次 App 运行期间不再提示，下次启动再提示。
- 连接成功后：
  - 保存 helper 返回的 `gateway`、`interface`、`routes`；
  - 更新状态副标题、警告条、菜单栏；
  - 日志记录每条结果。
- 断开/重连：
  - 清空本次生效状态；
  - 重连时重新传入当前配置；
  - “稍后”保存的配置在下次连接时生效。
- 设置保存：
  - 比较当前已保存配置与新配置；
  - 若已连接且 TUN 模式且配置变化：弹重连确认；
  - 否则直接保存。
- TUN 关闭/代理模式：
  - 不传 `direct_ips`，不加路由；
  - 卡片仍可编辑；状态点灰色；菜单栏隐藏。

### 7.4 配置存储

- `direct_ip_enabled`: bool，默认 `false`；
- `direct_ips`: 换行分隔字符串，读取时解析为去重后的列表，默认空；
- 旧配置没有这两个键时按默认值处理；
- 保存时写入当前列表；关闭开关不清空列表。

## 8. 输入、校验与粘贴

### 8.1 支持的分隔符

```text
换行、回车
英文逗号 ,
中文逗号 ，
顿号 、
英文分号 ;
中文分号 ；
空格、Tab、全角空格
```

### 8.2 归一化

```text
全角数字 ０-９      -> 半角 0-9
全角点 ．           -> 半角 .
全角空格 　         -> 普通空格
IP 两侧的中文/英文引号、括号 -> 去掉
```

### 8.3 不支持

```text
CIDR（/24）
端口（:22）
IP 范围（10.182.37.18-20）
括号里的备注（10.182.37.18（公司））
域名、主机名
```

### 8.4 校验规则

- 只接受合法 IPv4；
- 空行忽略；自动去重；
- 最多 100 条；超过保存报错；
- 非法行红框 + 列表下方错误文字，阻止保存；
- 拒绝 `0.0.0.0`、`255.255.255.255`、回环、组播、广播、本机 IP、默认网关、VPN 服务器 IP；
- 允许私有 IP 和公网 IP；
- 与本地网卡同网段的 IP：允许保存，但不传给 helper、不添加路由；
  - 卡片状态点灰色，tooltip 提示“该 IP 已在本地网段，无需直连路由”；
  - 不计入失败，也不计入菜单栏的 `N/M`（菜单栏只统计实际加路由的 IP）；
  - 若生效集合为空，菜单栏直连行隐藏；
- VPN 服务器地址为域名时，连接前解析；解析成功则与服务器 IP 比较，失败则只做字符串比较并记录警告；
- 学校 IP 无法自动识别，UI 明确提示“只填公司/其他直连地址，不要填学校地址”。

- 粘贴拆分：中文逗号、顿号、中文分号、全角空格、引号/括号；

- 停止/内核退出时删除路由；
- App 状态模型：配置 vs 生效、“稍后”行为；
- 菜单栏显示规则；
- 警告条显示/关闭/重新评估；
- 设置保存 diff：集合未变不弹窗，集合变化弹窗；
- 配置读写兼容旧版本（默认关闭、空列表）。

### 9.2 手工功能验收

1. VPN 已连接，列表含 `10.182.37.18`：
   - `route -n get 10.182.37.18` 显示 `en0` / `10.0.0.1`；
   - `ssh ai@10.182.37.18` 通；
   - `ssh czr@10.8.18.32` 通。
2. VPN 已连接，列表为空：公司 SSH 超时（预期）；无警告条；菜单栏无直连行。
3. 加第二个公司 IP：两条路由都生效；菜单栏 `2 个`。
4. 删掉一个 IP，选“现在重连”：该路由被删除；菜单栏数量更新。
5. 开关关闭 + “稍后”：当前路由仍生效；菜单栏仍显示；卡片提示“当前连接仍生效，重连后关闭”；下次重连后消失。
6. 非法 IP、中文符号粘贴、重复 IP、100 条上限。
7. helper 未更新：提示更新/跳过；跳过时警告条 + `0/N`；本次运行不再提示。
8. 部分失败（模拟）：警告条 `1/2`；菜单栏 `1/2`；学校 VPN 正常。
9. 菜单栏行只在正确条件下显示；点击定位到卡片。
10. 警告条关闭后菜单栏保留；重连后重新评估。
11. VS Code Remote-SSH、`scp`、`rsync` 各验证一次。
12. FlClash 开启时：公司走 en0、学校走 utun、VPN 服务器 underlay 正常。
13. 睡眠唤醒/自动重连后路由重新应用。
14. App 崩溃/helper 退出后的路由清理。
15. TUN 关闭、Linux、Windows 的禁用/隐藏状态。

## 10. 风险与限制

- 公司 IP 必须从当前默认物理网关可达；否则路由加了也不通；
- 不处理另一张网卡/另一个公司 VPN；
- 不处理 CIDR；公司机器多时需要逐条添加；
- 学校 IP 需要用户自己不要填；
- helper 需要重装一次；
- 换网后需要重连 VPN 才会使用新网关；
- 使用跳板机时，需要把跳板机 IP 也加入直连列表；
- 路由存在不等于公司服务可达；App 只报告“路由已加”，不保证 TCP 可达；
- 学校 VPN 若未来下发更具体的公司与校园重叠路由，可能需要重新评估路由覆盖顺序；
- 路由冲突/已存在时，helper 尽量识别并报告，不保证自动修复所有第三方路由。
